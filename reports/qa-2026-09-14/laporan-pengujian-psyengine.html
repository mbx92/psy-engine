Penilaian kelayakan

Belum layak dinyatakan siap produksi penuh

Kunci jawaban CFIT terbukti dapat diakses tanpa login. Jalur registrasi publik pada kode membuat admin, dan beberapa kontrol integritas jawaban serta penilaian belum memadai. Prioritaskan penutupan kebocoran soal dan registrasi, kemudian perbaiki kontrol sesi dan scoring sebelum penerimaan produksi.

Kesimpulan ini adalah penilaian teknis berdasarkan cakupan di bawah, bukan sertifikasi keamanan atau validasi psikometrik. Temuan berlabel server terverifikasi dibuktikan pada deployment; temuan lokal/mock membuktikan perilaku kode lokal; temuan tinjauan kode masih perlu uji integrasi terarah. Versi commit deployment belum dicocokkan dengan kode lokal.

Hal yang bekerja: halaman login dapat dibuka, form kosong dicegah, halaman admin mengarahkan pengguna anonim ke login, enam endpoint terlindungi menolak akses anonim (401), dan tautan undangan tidak valid memberi pesan yang jelas. Build produksi lokal serta skrip regresi monitoring yang tersedia berhasil.

F01 · KritisServer terverifikasi

Kunci jawaban CFIT tersedia tanpa login

Bukti
GET /api/tests/cfit-scale-2 tanpa cookie/Authorization mengembalikan HTTP 200: 50 entri soal, dengan field answer pada 46 soal. PAPI juga mengirim bobot opsi pada 90 soal. Isi jawaban tidak disalin ke laporan.
Dampak
Orang yang dapat menjangkau server dapat memperoleh kunci sebelum mengerjakan tes; hasil asesmen dapat dimanipulasi.
Reproduksi
Kirim GET anonim ke /api/tests/cfit-scale-2. Hitung entri questions yang memiliki field answer. Hasil pengujian: 46. Endpoint sesi juga mengirim scoringConfig penuh menurut kode, tetapi alur sesi nyata belum diuji.
Lokasi kode
server/api/tests/[slug].get.js:19; server/api/sessions/token/[token].get.js:31
Perbaikan
Pisahkan model soal untuk peserta dan model penilaian server. Hapus answer, weight dan konfigurasi penilaian rahasia dari seluruh respons peserta; batasi pengiriman soal ke sesi yang berhak.
Kriteria lulus
GET anonim tidak mengirim bank soal; respons peserta yang sah tidak memuat kunci atau bobot penilaian.
F02 · KritisKode + endpoint server terbuka

Pendaftaran publik membuat akun admin

Bukti
Middleware mengecualikan /api/auth/register dari autentikasi. Handler menyimpan role: 'admin' dan menerbitkan JWT. POST anonim dengan body kosong di server menghasilkan 400 validasi, bukan 401/403. Akun baru tidak dibuat dalam pengujian ini.
Dampak
Jika handler server sesuai kode lokal, siapa pun yang menjangkau endpoint dapat membuat akun admin. Hak efektif mengikuti permission role admin pada database.
Reproduksi
Tinjau bypass autentikasi dan assignment role dalam kode. Verifikasi server secara nonmutasi dengan POST {} ke /api/auth/register. Pembuktian pembuatan admin penuh masih memerlukan lingkungan uji/otorisasi khusus.
Lokasi kode
server/api/auth/register.post.js:27; server/middleware/auth.js:11
Perbaikan
Tutup registrasi publik pada produksi, atau wajibkan undangan dan persetujuan admin. Gunakan peran awal paling terbatas dan hindari penerbitan akses admin otomatis.
Kriteria lulus
Pengguna anonim tidak dapat membuat admin; hanya pihak dengan izin pengelolaan pengguna dapat memberikan peran tersebut.
F03 · TinggiServer + tinjauan kode

Login disajikan melalui HTTP tanpa enkripsi

Bukti
URL yang diuji tetap http://10.100.10.100:8880/login dan mengembalikan 200 tanpa pengalihan ke HTTPS. useAuth menyimpan token lewat cookie sisi klien dengan sameSite:lax, tanpa Secure/HttpOnly.
Dampak
Kredensial dan sesi dapat terekspos kepada pihak yang mampu mengamati lalu lintas jaringan. Cookie yang dapat dibaca JavaScript memperbesar dampak jika terjadi XSS; XSS sendiri tidak dibuktikan.
Reproduksi
Buka URL login dan periksa skema URL serta header respons. Tinjau COOKIE_OPTS dan persist di useAuth.
Lokasi kode
composables/useAuth.js:1; server/api/auth/login.post.js
Perbaikan
Gunakan HTTPS untuk akses pengguna dan pengalihan HTTP. Kelola sesi lewat cookie Secure dan HttpOnly dari server, dengan penanganan CSRF yang sesuai.
Kriteria lulus
Login dan sesi berjalan hanya di HTTPS; atribut cookie diverifikasi dari respons server.
F04 · TinggiTinjauan kode

Bukti

Reproduksi
Di staging, login akun uji, simpan token, nonaktifkan/turunkan peran akun dengan admin lain, lalu ulangi akses menggunakan token lama. Skenario mutasi ini belum dijalankan pada server.
Lokasi kode
server/utils/auth.js:16; server/middleware/auth.js:41; server/utils/access.js:13; server/api/auth/password.put.js; server/api/auth/logout.post.js
Perbaikan
Periksa akun aktif dan peran terkini pada setiap request atau gunakan session/token version yang dapat dicabut. Cabut sesi saat perubahan keamanan akun.
Kriteria lulus
Token lama ditolak segera setelah penonaktifan/pencabutan; perubahan peran langsung berlaku di API.

Bukti

Urutan tindak lanjut

  1. Sebelum sesi tes baru: tutup akses anonim ke bank soal/kunci dan registrasi admin publik; verifikasi akses ulang tanpa login. Periksa akun yang pernah dibuat melalui registrasi dan kemungkinan paparan kunci dengan pemilik sistem.
  2. Sebelum penerimaan produksi: aktifkan HTTPS dan sesi yang dapat dicabut; perbaiki deadline server, validasi jawaban, status kegagalan scoring, serta penanganan norma yang hilang.
  3. Regresi integrasi di staging: gunakan data sintetis dan akun berbeda per peran. Uji peserta → undangan → mulai → autosave → koneksi putus → lanjut → submit → laporan → verifikasi.
  4. Kualitas dan operasional: perbaiki validasi biodata/bobot, uji klaim kuota bersamaan, tambah uji peran dan scoring ke pipeline, serta uji backup-restore dan kapasitas sesuai jumlah peserta yang ditargetkan.

Syarat penerimaan: semua temuan kritis diselesaikan dan diverifikasi ulang; temuan tinggi ditutup atau memiliki keputusan risiko terdokumentasi; alur tes dan laporan lulus dengan dataset referensi yang disetujui pemilik instrumen.
